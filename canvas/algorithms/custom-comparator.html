Custom Comparator — Implement from Scratch

Comparable = natural order (compareTo on the class itself). Comparator = custom order (separate function). Chain with thenComparing for multi-field sorts. Lambda syntax makes it concise. Essential for any sorting or ordered collection question.

Core Idea

Comparable — natural order

The class itself implements Comparable<T> and defines a single natural ordering via compareTo(T other).

  • Lives inside the class
  • One natural order per class
  • Used by Collections.sort(list)
  • String, Integer, etc. already implement it

Comparator — custom order

A separate object (or lambda) that defines compare(T a, T b). Create as many as you need for different sort orders.

  • Lives outside the class
  • Multiple custom orders possible
  • Used by list.sort(comparator)
  • Lambda: (a, b) -> …

How chaining works: If the primary comparator returns 0 (equal), the secondary comparator breaks the tie. If that also returns 0, the tertiary comparator is tried. Exactly like SQL ORDER BY dept, age, name.

Return Value Convention

compareTo / compare returns

  • Negative → first comes before second
  • Zero → equal ordering
  • Positive → first comes after second

Think: a.compareTo(b) returns a - b conceptually (ascending). Return b - a for descending.

Common pitfall

Never use return a - b for integers — it can overflow! Use Integer.compare(a, b) or Double.compare(a, b) instead.

Integer.MIN_VALUE - 1 wraps to Integer.MAX_VALUE, giving the wrong sign.

Record with Comparable

natural order

Java 16+ record gives free constructor, getters, equals, hashCode, toString. We add Comparable for natural ordering by name.

record Employee(String name, String dept, int age, double salary)
        implements Comparable<Employee> {

    @Override
    public int compareTo(Employee o) {
        return this.name.compareTo(o.name);   // natural order: by name
    }
}

Custom Comparator — Single Field

Comparator

Sort by salary descending using a method reference + .reversed().

// By salary descending
emps.sort(Comparator.comparingDouble(Employee::salary).reversed());

// Equivalent lambda form
emps.sort((a, b) -> Double.compare(b.salary(), a.salary()));

Multi-Field Chaining

thenComparing

Sort by department, then by age, then by name — like SQL ORDER BY dept, age, name.

emps.sort(
    Comparator.comparing(Employee::dept)          // primary: department
        .thenComparingInt(Employee::age)             // secondary: age
        .thenComparing(Employee::name)               // tertiary: name
);
Use specialized variants for primitives: comparingInt, comparingDouble, thenComparingInt. They avoid autoboxing overhead compared to comparing() with a wrapper type.
5

Lambda Comparator

concise form
// Full lambda (most flexible)
emps.sort((a, b) -> Double.compare(b.salary(), a.salary()));

// Method reference (cleanest for single field)
emps.sort(Comparator.comparing(Employee::name));

// Reversed
emps.sort(Comparator.comparing(Employee::name).reversed());

Common Follow-ups

Comparator.nullsFirst / nullsLast?

Wraps a comparator to handle null values safely. Comparator.nullsFirst(Comparator.comparing(Employee::name)) puts nulls before all non-null values. nullsLast puts them at the end. Without these wrappers, null fields throw NullPointerException.

TreeMap with custom comparator?

new TreeMap<>(comparator) uses the comparator for key ordering instead of natural order. Common use: case-insensitive map with String.CASE_INSENSITIVE_ORDER. Also used for custom key types that don't implement Comparable. All operations remain O(log n).

PriorityQueue ordering?

Default PriorityQueue is a min-heap using natural order. For max-heap: new PriorityQueue<>(Comparator.reverseOrder()) or Collections.reverseOrder(). Custom: new PriorityQueue<>(Comparator.comparingInt(Task::priority)). The comparator defines what "minimum" means.

Collections.reverseOrder()?

Returns a comparator that reverses the natural ordering. Collections.sort(list, Collections.reverseOrder()) sorts descending. For custom types: Comparator.comparing(Employee::salary).reversed() is the modern equivalent. Both produce a "reversed" comparator wrapper.

Edge Cases & Gotchas

Integer overflow in compareTo — Never write return this.age - other.age. If ages could be Integer.MIN_VALUE and Integer.MAX_VALUE, subtraction overflows. Always use Integer.compare(a, b).
Inconsistent with equals — If compareTo returns 0 but equals returns false, TreeSet/TreeMap will treat them as the same key. The contract says: compareTo == 0 should imply equals == true.
Records + Comparable — Records auto-generate equals/hashCode from all fields, but you must manually implement compareTo if you want natural ordering. The auto-generated equals may be broader than your compareTo — be careful with ordered collections.
