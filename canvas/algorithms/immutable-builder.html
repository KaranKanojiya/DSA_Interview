Immutable Class + Builder Pattern — Implement from Scratch

Core Idea

Immutable Class — 5 Rules

  1. final class — prevent subclassing that could break guarantees
  2. private final fields — no reassignment after construction
  3. No setters — state cannot change
  4. Defensive copies — for mutable fields (List, Date, arrays), copy on input and output
  5. Constructor or Builder — all state set at creation time

Builder Pattern — Why?

  • Avoids telescoping constructors — no Person(name, age, null, null, hobbies, null)
  • Separates required vs optional params clearly
  • Fluent API: new Builder("K",30).hobby("X").build()
  • Returns a frozen, immutable object — safe to share across threads
2

Builder Construction Flow

Defensive copy is the key. The Builder's hobbies is a mutable ArrayList. On build(), we call List.copyOf(builder.hobbies) — the immutable object gets its own unmodifiable snapshot. Later changes to the Builder don't affect the built object.

Immutability Rules Walkthrough

final class

Prevents a subclass from adding a setter or overriding a getter to return mutable state. Ensures the immutability contract can't be broken by inheritance.

private final fields

private — no direct access from outside. final — the reference can't be reassigned after the constructor. Combined: fields are locked at construction time.

Defensive copy — why?

Without List.copyOf(), the caller could keep a reference to the original list and mutate it after construction:
list.add("Evil") → the "immutable" object's hobbies change. Defensive copy breaks this link.

No setters, ever

An immutable object has zero mutation methods. Need a modified version? Create a new object via the Builder: new Builder(old).hobby("New").build().

ImmutablePerson — The Immutable Class

final class

All 5 immutability rules applied: final class, private final fields, no setters, defensive copy, private constructor (use Builder).

public final class ImmutableClassBuilder {

    static final class ImmutablePerson {
        private final String name;
        private final int age;
        private final List<String> hobbies;

        // Private constructor — use Builder
        private ImmutablePerson(Builder builder) {
            this.name = builder.name;
            this.age = builder.age;
            this.hobbies = List.copyOf(builder.hobbies);  // defensive copy
        }

        // Getters only — no setters
        public String getName() { return name; }
        public int getAge() { return age; }
        public List<String> getHobbies() { return hobbies; }

        @Override
        public String toString() {
            return "Person{name='" + name + "', age=" + age
                   + ", hobbies=" + hobbies + "}";
        }
    }
}

Builder — Fluent Construction

inner class

Required params in the Builder constructor. Optional params via chainable methods. build() creates the immutable object.

static class Builder {
    private String name;                              // required
    private int age;                                   // required
    private List<String> hobbies = new ArrayList<>(); // optional

    // Required params go in constructor
    Builder(String name, int age) {
        this.name = name;
        this.age = age;
    }

    // Optional — fluent chaining (returns this)
    Builder hobby(String hobby) {
        hobbies.add(hobby);
        return this;
    }

    Builder hobbies(List<String> hobbies) {
        this.hobbies.addAll(hobbies);
        return this;
    }

    // Terminal — creates the immutable object
    ImmutablePerson build() {
        return new ImmutablePerson(this);
    }
}

Main — Demo & Mutation Test

runnable
public static void main(String[] args) {
    // Build immutable person
    ImmutablePerson person = new ImmutablePerson.Builder("Karan", 30)
            .hobby("Coding")
            .hobby("Reading")
            .build();
    System.out.println("Created: " + person);

    // Try to modify — fails!
    try {
        person.getHobbies().add("Hacking");
    } catch (UnsupportedOperationException e) {
        System.out.println("Cannot modify: " + e.getClass().getSimpleName());
    }
    System.out.println("After attempt: " + person);
}

Common Follow-ups

Java Records as lightweight immutables?

record Person(String name, int age, List<String> hobbies) {} — Java 16+ gives you final class, private final fields, auto getters, equals/hashCode/toString for free. Caveat: the record doesn't do defensive copying — List.copyOf() still must be done in a compact constructor. Records are great for DTOs but can't extend classes.

Lombok @Builder?

Lombok's @Builder annotation auto-generates the Builder class at compile time via annotation processing. Combine with @Value (immutable) for both patterns. Trade-off: hides the code — you can't see the Builder in your source. Interviewers want you to write it by hand to prove you understand the mechanics.

Immutable collections — List.of, Map.of?

Java 9+ factory methods: List.of(1,2,3), Map.of("a",1), Set.of(). These return truly unmodifiable collections — no add(), put(), or remove(). They also disallow null elements. List.copyOf() creates an unmodifiable copy of an existing collection. Use these in immutable classes instead of wrapping with Collections.unmodifiableList().

Why is String immutable?

String is final with a private final byte[] value. Benefits: string pool caching (safe to share references), thread safety (no synchronization needed), hash code caching (computed once, used in HashMap keys), security (class loading, network connections use Strings — mutability would be a vulnerability). This is the most-asked "why" question about Java.

Copy-on-write pattern?

Instead of always copying, share the underlying data and only copy when a mutation is requested. CopyOnWriteArrayList does this: reads see the current snapshot, writes create a new array. Useful when reads vastly outnumber writes. Persistent data structures (Clojure's PersistentVector) use structural sharing for O(log n) copy-on-write.

Edge Cases & Gotchas

Forgetting defensive copy — The #1 mistake. If you assign this.hobbies = builder.hobbies directly, the caller's list and the object share a reference. Mutation via the original list breaks immutability silently.
Date/Calendar fields — These are mutable! For Date birthDate, you need new Date(builder.birthDate.getTime()) in constructor AND new Date(birthDate.getTime()) in the getter. Better: use LocalDate (Java 8+ immutable time API).
Arrays are always mutable — final int[] scores means the reference is final, but the contents are mutable. Always Arrays.copyOf() in constructor and getter, or use List.of() instead.
Builder reuse — Can you call build() twice on the same Builder? With List.copyOf(), yes — each call creates a separate snapshot. Without defensive copy, both objects would share the same mutable list.
