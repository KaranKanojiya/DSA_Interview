Convert a string to a 32-bit signed integer, handling whitespace, signs, digits, overflow, and invalid characters. The classic 4-step parsing problem: skip whitespace → check +/- sign → parse digits → clamp to INT range. Uses a long intermediate to detect overflow before casting.

Core Idea

What is atoi?

A function that converts a string representation of a number into its integer value. Named after the C standard library function atoi() ("ASCII to integer").

Input: " -42abc" → Output: -42

Why build from scratch?

  • Tests precise edge-case handling — whitespace, signs, non-digits, overflow
  • Interviewers want to see you handle INT overflow correctly
  • Integer.parseInt() exists, but throws exceptions — atoi should return clamped values

Overflow Handling — Why long?

The Overflow Problem

If input is "2147483648" (INT_MAX + 1), an int result would silently wrap around to a negative number. We use long as an intermediate accumulator to detect overflow before casting.

Clamp Strategy

After each digit, check:
if (result * sign > INT_MAX) return INT_MAX;
if (result * sign < INT_MIN) return INT_MIN;

Check inside the loop, not after — prevents long overflow on enormous strings.

Full Implementation

53 lines

Single method — no inner classes, no extra data structures. A long accumulator and careful bounds checking are all you need.

public static int myAtoi(String s) {
    if (s == null || s.isEmpty()) return 0;

    int i = 0, n = s.length();

    // Step 1: Skip leading whitespace
    while (i < n && s.charAt(i) == ' ') i++;
    if (i == n) return 0;

    // Step 2: Check sign
    int sign = 1;
    if (s.charAt(i) == '+' || s.charAt(i) == '-') {
        sign = s.charAt(i) == '-' ? -1 : 1;
        i++;
    }

    // Step 3: Parse digits, handle overflow
    long result = 0;
    while (i < n && Character.isDigit(s.charAt(i))) {
        result = result * 10 + (s.charAt(i) - '0');

        // Step 4: Clamp to INT range
        if (result * sign > Integer.MAX_VALUE) return Integer.MAX_VALUE;
        if (result * sign < Integer.MIN_VALUE) return Integer.MIN_VALUE;
        i++;
    }

    return (int) (result * sign);
}

Step-by-Step Breakdown

annotated

Step 1 — Skip Whitespace

while (i < n && s.charAt(i) == ' ')
    i++;
if (i == n) return 0;

Advance index past all leading spaces. If the string is all spaces, return 0.

Step 2 — Read Sign

int sign = 1;
if (s.charAt(i) == '+' || s.charAt(i) == '-') {
    sign = s.charAt(i) == '-' ? -1 : 1;
    i++;
}

Default positive. Only consume ONE sign character. "+-42" → stop after '+'.

Step 3 — Parse Digits

long result = 0;
while (i < n && Character.isDigit(s.charAt(i))) {
    result = result * 10 + (s.charAt(i) - '0');
    // clamp check inside loop
    i++;
}

Multiply-and-add: result = result * 10 + digit. Stop at first non-digit.

Step 4 — Clamp to INT Range

if (result * sign > Integer.MAX_VALUE)
    return Integer.MAX_VALUE;
if (result * sign < Integer.MIN_VALUE)
    return Integer.MIN_VALUE;

Check inside the loop after each digit. Using long for result means we can safely detect overflow before it wraps.

Common Follow-ups

How does Integer.parseInt() differ?

parseInt() throws NumberFormatException on invalid input. atoi returns 0 or clamped value. parseInt uses a similar digit loop but validates the entire string first — no "stop at first non-digit" behavior.

Handle hex/octal/binary?

After sign, check prefix: 0x → base 16, 0b → base 2, 0 → base 8. In the digit loop, use the base: result = result * base + digitValue. Digit values: for hex, 'a'-'f' → 10-15. Java's Integer.parseInt(s, radix) handles this.

BigInteger for arbitrary precision?

For strings too large for long, use an array of digits (like BigInteger internals). Multiply-and-add becomes array operations. Java's BigInteger(String) does exactly this. Trade-off: O(n²) for multiply vs O(n) for int atoi.

Locale-aware parsing?

Different locales use different separators: 1,000.50 (US) vs 1.000,50 (DE). Use NumberFormat.getInstance(Locale) for locale-aware parsing. atoi in interviews always assumes ASCII digits and period decimal — no locale handling needed.

Edge Cases & Gotchas

Overflow inside the loop — If you check overflow after the loop, the long itself can overflow on astronomically long digit strings. Always clamp inside the while loop, after each digit.
Only one sign allowed — "+-42" should return 0. After reading one sign, the next char must be a digit or we stop. Don't look for a second sign.
Empty / all-spaces — Return 0. Don't forget the if (i == n) check after skipping whitespace — prevents IndexOutOfBounds on the sign check.
Why long and not pure int? — The alternative is to check result > MAX/10 or result == MAX/10 && digit > MAX%10 before accumulating — correct but harder to read. Using long is cleaner and perfectly valid in interviews.
