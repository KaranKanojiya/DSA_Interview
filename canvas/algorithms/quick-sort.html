Core Idea

What is Quick Sort?

A divide-and-conquer sorting algorithm that picks a pivot element, partitions the array around it (elements < pivot on left, > pivot on right), then recursively sorts both partitions.

The key insight: after partitioning, the pivot is in its final sorted position — it never needs to move again.

Why it matters

  • In-place — O(log n) stack space only, no extra arrays
  • Cache-friendly — operates on contiguous memory
  • Java uses dual-pivot QuickSort for primitives
  • Foundation for QuickSelect (find kth element in O(n) avg)

Lomuto Partition — Visual Walkthrough

Array: [10, 80, 30, 90, 40, 50, 70] — pivot chosen randomly, swapped to end. Let's say pivot = 50.

Lomuto partition uses a single scan pointer j and a boundary pointer i. Elements < pivot get swapped into the "left zone" (indices 0..i). Simple to implement and reason about.

Why Random Pivot?

Worst case: O(n²)

If pivot is always the smallest (or largest) element, one partition has n-1 elements and the other has 0. This creates n levels instead of log n.

Happens with sorted input + always picking first/last element as pivot.

Random pivot fixes it

Randomly selecting the pivot makes the worst case astronomically unlikely. Expected depth is O(log n), giving O(n log n) with high probability.

Median-of-three (pick median of first, middle, last) is another common strategy.

sort() & quickSort() — Recursive Driver

entry point

Public entry point delegates to the recursive helper with low/high bounds.

private static final Random rand = new Random();

public static void sort(int[] arr) {
    quickSort(arr, 0, arr.length - 1);
}

private static void quickSort(int[] arr, int low, int high) {
    if (low >= high) return;            // base case: 0 or 1 element
    int pivotIndex = partition(arr, low, high);
    quickSort(arr, low, pivotIndex - 1);  // sort left of pivot
    quickSort(arr, pivotIndex + 1, high); // sort right of pivot
}

partition() — Lomuto Scheme

core logic

Random pivot avoids O(n²). Lomuto: single pass, i tracks boundary of "less than" region.

private static int partition(int[] arr, int low, int high) {
    // Pick random pivot, swap to end
    int randIdx = low + rand.nextInt(high - low + 1);
    swap(arr, randIdx, high);

    int pivot = arr[high];
    int i = low - 1;                    // boundary of "less than pivot"

    for (int j = low; j < high; j++) {
        if (arr[j] < pivot) {
            i++;
            swap(arr, i, j);           // move small element to left zone
        }
    }
    swap(arr, i + 1, high);            // place pivot in correct position
    return i + 1;                      // return pivot's final index
}

swap() — Helper

utility
private static void swap(int[] arr, int i, int j) {
    int temp = arr[i];
    arr[i] = arr[j];
    arr[j] = temp;
}

Common Follow-ups

3-way partition (Dutch National Flag)?

When there are many duplicates, Lomuto degrades because equal elements are split arbitrarily. 3-way partition divides into < pivot, == pivot, > pivot using three pointers (lo, mid, hi). Equal elements are never recursed on. O(n) for arrays with few distinct values.

Hoare partition vs Lomuto?

Lomuto: simpler, single scan from left, ~3× more swaps. Hoare: two pointers from both ends moving inward, fewer swaps (~n/6 vs ~n/3), faster in practice. Hoare doesn't place the pivot in its final position — the returned index is just a split point, not the pivot's location.

QuickSelect for kth element?

Same partitioning, but only recurse into the side containing the kth element. Average O(n) — at each step we throw away half the elements. Used in Arrays.sort internals and LeetCode #215 (Kth Largest Element).

Introsort (quick + heap)?

Start with QuickSort, but if recursion depth exceeds 2×log(n), switch to HeapSort to guarantee O(n log n) worst case. C++ STL's std::sort uses this approach. Combines QuickSort's average-case speed with HeapSort's worst-case guarantee.

Why is QuickSort not stable?

During partitioning, elements equal to the pivot can be swapped past each other, changing their relative order. Example: [3a, 2, 3b, 1] with pivot=2 — the swap moves 1 past both 3s, but 3a and 3b may end up reordered relative to each other. Making it stable requires O(n) extra space, defeating the in-place advantage.

Edge Cases & Gotchas

Sorted input + fixed pivot = O(n²) — Always picking first or last element as pivot on already-sorted input creates maximally unbalanced partitions. Random pivot or median-of-three eliminates this.
All equal elements — Lomuto partition with all-equal input still creates unbalanced partitions (all elements go left). Use 3-way partition for duplicate-heavy data.
Stack overflow on large n — Deep recursion (O(n) in worst case) can overflow the stack. Tail-call optimization: always recurse on the smaller partition first, use iteration for the larger one.
