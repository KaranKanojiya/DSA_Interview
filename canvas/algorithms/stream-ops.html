Core Idea

What is a Stream Pipeline?

A source of elements flows through a chain of intermediate operations (filter, map, sorted) and terminates with a terminal operation (reduce, toList, forEach). Each intermediate op returns a new stream — the original is unchanged.

Inspired by Java 8 Streams, but implemented with simple loops over an internal List<T>.

Why build from scratch?

  • Tests understanding of functional interfaces: Predicate, Function, BinaryOperator
  • Shows you understand generics and method chaining
  • Interviewers probe: "how would you make this truly lazy?" → Spliterator discussion
  • Google/Amazon ask this to test API design instincts

Operation Categories

Intermediate (return MyStream)

  • filter(Predicate<T>) — keep matching elements
  • map(Function<T,R>) — transform each element
  • flatMap(Function<T, MyStream<R>>) — 1-to-many + flatten
  • distinct() — remove duplicates (LinkedHashSet)
  • sorted(Comparator<T>) — sort elements
  • limit(n) — take first n elements

Terminal (produce a value)

  • reduce(identity, BinaryOperator) — fold into single value
  • forEach(Consumer<T>) — side effect on each element
  • toList() — collect into List
  • findFirst() → Optional<T>
  • count() → long

Each Operation at a Glance

filter

Loop over data, keep items where predicate.test(item) is true. Returns new MyStream with subset.

map

Loop over data, apply fn.apply(item) to each. Type can change: MyStream<T> → MyStream<R>.

flatMap

Like map, but each element produces a stream. All results are flattened into one stream. 1-to-many expansion.

reduce

Start with identity, apply accumulator(result, item) for each element. Folds the stream into a single value.

distinct

Wrap data in LinkedHashSet (preserves insertion order, removes dupes), then back to list.

sorted

Copy data, list.sort(comparator). O(n log n). Stateful intermediate operation — needs all elements before producing output.

MyStream Class — Core

wrapper

A generic wrapper around List<T>. Each operation creates a new MyStream with the transformed data — immutable-style chaining.

static class MyStream<T> {
    private final List<T> data;

    MyStream(List<T> data) { this.data = data; }
}
2

filter — Keep Matching Elements

Predicate<T>
MyStream<T> filter(Predicate<T> predicate) {
    List<T> result = new ArrayList<>();
    for (T item : data) {
        if (predicate.test(item)) result.add(item);
    }
    return new MyStream<>(result);
}
3

map — Transform Each Element

Function<T,R>
<R> MyStream<R> map(Function<T, R> mapper) {
    List<R> result = new ArrayList<>();
    for (T item : data) {
        result.add(mapper.apply(item));
    }
    return new MyStream<>(result);
}
4

flatMap — Map + Flatten

1-to-many
<R> MyStream<R> flatMap(Function<T, MyStream<R>> mapper) {
    List<R> result = new ArrayList<>();
    for (T item : data) {
        result.addAll(mapper.apply(item).toList());
    }
    return new MyStream<>(result);
}
5

reduce — Fold into Single Value

BinaryOperator<T>
T reduce(T identity, BinaryOperator<T> accumulator) {
    T result = identity;
    for (T item : data) {
        result = accumulator.apply(result, item);
    }
    return result;
}

Terminal & Utility Operations

consumers
// Terminal operations
Optional<T> findFirst() {
    return data.isEmpty() ? Optional.empty() : Optional.of(data.get(0));
}
long count() { return data.size(); }
List<T> toList() { return new ArrayList<>(data); }
void forEach(Consumer<T> action) {
    for (T item : data) action.accept(item);
}

// Intermediate utilities
MyStream<T> distinct() {
    return new MyStream<>(new ArrayList<>(new LinkedHashSet<>(data)));
}
MyStream<T> sorted(Comparator<T> cmp) {
    List<T> result = new ArrayList<>(data);
    result.sort(cmp);
    return new MyStream<>(result);
}
MyStream<T> limit(int n) {
    return new MyStream<>(data.subList(0, Math.min(n, data.size())));
}

Common Follow-ups

True lazy evaluation with Spliterator?

Our MyStream is eager — each intermediate op creates a full new list. Real Java Streams use a Spliterator pipeline where elements flow through all stages one at a time. A filter().map().findFirst() chain stops as soon as one element passes — no full iteration.

Key: store operations as a linked chain of lambdas. Only evaluate when a terminal op triggers the pipeline.

Parallel streams?

Java's parallelStream() uses ForkJoinPool. The Spliterator's trySplit() divides the source; each chunk is processed by a different thread. The results are then combined. Key pitfall: shared mutable state in lambdas breaks parallelism. Reduce must be associative for correct parallel folding.

Short-circuiting (findFirst, anyMatch)?

Short-circuit operations stop the pipeline early. findFirst() needs only one element. anyMatch(pred) stops at first true. limit(n) stops after n elements pass. In a lazy pipeline, upstream stages aren't even asked for more elements. Our eager impl processes everything upfront — a key limitation.

Collector / groupingBy?

A Collector<T,A,R> encapsulates: supplier (create accumulator), accumulator (add element), combiner (merge two accumulators), finisher (extract result). groupingBy() returns a Map<K, List<V>> by classifying each element. Implementing a custom Collector tests understanding of the 4-function protocol.

Backpressure in reactive streams?

Reactive Streams (Project Reactor, RxJava) add backpressure: the subscriber tells the publisher how many items it can handle. Flux.range(1,1M).filter(...).map(...) won't OOM because the subscriber controls flow rate. Java 9's Flow API standardizes this with Publisher, Subscriber, Subscription, Processor.

Edge Cases & Gotchas

Stream reuse — Java Streams can only be consumed once. Our MyStream doesn't enforce this (it's just a List wrapper), but in real code, calling a terminal op on a consumed stream throws IllegalStateException.
Eager vs lazy — Our implementation materializes intermediate results into Lists. A 1M-element stream through 3 filters creates 3 intermediate lists. Real Streams avoid this entirely via lazy pipeline fusion.
Type safety with generics — map() changes the generic type: MyStream<String>.map(String::length) returns MyStream<Integer>. The <R> type parameter on the method makes this work.
reduce identity — The identity must be a true identity for the accumulator: acc.apply(identity, x) == x. For sum, identity=0. For product, identity=1. Wrong identity = wrong result, especially in parallel streams.
