Core Idea

What is Merge Sort?

A divide-and-conquer sorting algorithm that recursively splits the array into halves until each piece has 1 element (base case), then merges pairs back together in sorted order.

The "merge" step does the real work — combines two sorted arrays into one sorted array using a two-pointer technique.

Why it matters

  • Guaranteed O(n log n) — no worst-case degradation like QuickSort
  • Stable — equal elements keep their original order (<= in merge)
  • Foundation for external sorting (sorting data too large for RAM)
  • Used in Java's Arrays.sort() for objects (TimSort is merge-sort-based)

Merge Step — Two-Pointer Detail

How merge() works

  1. Start two pointers i=0 (left), j=0 (right)
  2. Compare left[i] vs right[j]
  3. Copy the smaller element into arr[k]
  4. Advance the pointer of the copied element
  5. When one side exhausted, copy remaining from other

Why <= for stability?

Using left[i] <= right[j] means when elements are equal, we pick from the left array first — preserving original order of equal elements.

If you use < instead, equal elements from the right array would come first, breaking stability.

sort() — Recursive Split

divide

Split the array into two halves and recursively sort each. Base case: array of size ≤ 1 is already sorted.

public static void sort(int[] arr) {
    if (arr.length <= 1) return;             // base case
    int mid = arr.length / 2;
    int[] left = Arrays.copyOfRange(arr, 0, mid);
    int[] right = Arrays.copyOfRange(arr, mid, arr.length);
    sort(left);                              // recurse left half
    sort(right);                             // recurse right half
    merge(arr, left, right);                 // merge sorted halves back
}

merge() — Two-Pointer Combine

conquer

Two sorted arrays merged into one. The <= comparison makes the sort stable.

private static void merge(int[] arr, int[] left, int[] right) {
    int i = 0, j = 0, k = 0;
    while (i < left.length && j < right.length) {
        if (left[i] <= right[j])                // <= makes it STABLE
            arr[k++] = left[i++];
        else
            arr[k++] = right[j++];
    }
    while (i < left.length) arr[k++] = left[i++];  // remaining left
    while (j < right.length) arr[k++] = right[j++]; // remaining right
}

Common Follow-ups

Bottom-up iterative merge sort?

Instead of recursing top-down, start with sub-arrays of size 1 and iteratively merge pairs: size 1 → 2 → 4 → 8… until the whole array is sorted. Same O(n log n) time, avoids recursion stack overhead. Useful in environments with limited stack space.

External merge sort for large files?

When data doesn't fit in RAM: (1) split file into chunks that fit in memory, (2) sort each chunk with any sort, (3) write sorted chunks to disk, (4) k-way merge the sorted chunks using a min-heap. Used by databases, Hadoop MapReduce, and sort command on Unix.

TimSort — the hybrid approach?

Python and Java's Arrays.sort(Object[]) use TimSort: identifies natural "runs" (already sorted subsequences), extends them with insertion sort, then merges runs with merge sort. Best case O(n) for nearly-sorted data. Stable. Invented by Tim Peters (2002).

Merge K sorted arrays?

Use a min-heap of size K. Push the first element of each array. Pop min, add to result, push next element from that array. O(N log K) where N = total elements. LeetCode #23 (merge K sorted linked lists) is the same idea.

Count inversions?

An inversion is a pair (i, j) where i < j but arr[i] > arr[j]. Modified merge sort counts inversions during the merge step: whenever we pick from the right array, all remaining elements in the left array are inversions. O(n log n) — much better than the O(n²) brute force.

Edge Cases & Gotchas

O(n) extra space — Unlike QuickSort, merge sort needs temporary arrays. This matters for very large datasets in memory-constrained environments. In-place merge sort exists but is complex and slower in practice.
Stability depends on <= — Using strict < instead of <= in the merge comparison breaks stability. Interviewers often ask about this detail.
Best for linked lists — Merge sort on linked lists uses O(1) extra space (just pointer manipulation), making it the preferred sorting algorithm for linked lists. No random access needed.
