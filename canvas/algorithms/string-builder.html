StringBuilder — Implement from Scratch

Dynamic char[] buffer with 2× growth strategy. append() is O(1) amortized, avoiding the O(n²) cost of repeated string concatenation. Supports insert, delete, reverse, and charAt. The key insight: strings are immutable, so every s += "x" creates a new copy.

Core Idea

The O(n²) problem

Strings in Java are immutable. Every s += "x" creates a new char[], copies the old content, appends the new character. For n appends: 1+2+3+…+n = O(n²) total copies.

This is the #1 reason StringBuilder exists.

The solution: mutable buffer

  • Internal char[] with extra capacity
  • 2× growth when full — amortized O(1) append
  • Direct mutation — no copies on every operation
  • Same idea as ArrayList (dynamic array)

Operations Overview

append(str)

  1. Check if buffer has room: ensureCapacity(length + str.length)
  2. Copy str chars into buffer at position length
  3. Increment length

Returns this for chaining: sb.append("a").append("b")

insert(index, str)

  1. ensureCapacity
  2. Shift existing chars right by str.length using arraycopy
  3. Copy str chars into the gap at index
  4. Increment length

O(n) — must shift all chars after index.

Fields & Constructor

setup

Internal char array starts at 16 (same default as Java's StringBuilder). length tracks how many chars are actually used.

private char[] buffer;
private int length;

public MyStringBuilder() {
    buffer = new char[16];
    length = 0;
}
2

append() — O(1) Amortized

core operation
public MyStringBuilder append(String str) {
    ensureCapacity(length + str.length());
    str.getChars(0, str.length(), buffer, length);
    length += str.length();
    return this;                       // fluent API for chaining
}

public MyStringBuilder append(char c) {
    ensureCapacity(length + 1);
    buffer[length++] = c;
    return this;
}
3

ensureCapacity() — 2× Growth

resize logic

The heart of amortized O(1). Double the buffer when current capacity is insufficient. Math.max handles cases where a single append exceeds 2× (e.g., appending a very long string).

private void ensureCapacity(int minCapacity) {
    if (minCapacity > buffer.length) {
        buffer = Arrays.copyOf(buffer,
            Math.max(buffer.length * 2, minCapacity));
    }
}
4

insert() & delete() — O(n)

shifting operations

Insert: shift right, copy into gap

public MyStringBuilder insert(int index, String str) {
    if (index < 0 || index > length)
        throw new IndexOutOfBoundsException();
    ensureCapacity(length + str.length());
    System.arraycopy(buffer, index,
        buffer, index + str.length(),
        length - index);
    str.getChars(0, str.length(), buffer, index);
    length += str.length();
    return this;
}

Delete: shift left, shrink length

public MyStringBuilder delete(int start, int end) {
    System.arraycopy(buffer, end,
        buffer, start, length - end);
    length -= (end - start);
    return this;
}

reverse() & toString()

utilities
public MyStringBuilder reverse() {
    for (int i = 0, j = length - 1;
         i < j; i++, j--) {
        char temp = buffer[i];
        buffer[i] = buffer[j];
        buffer[j] = temp;
    }
    return this;
}
public char charAt(int index) {
    return buffer[index];
}

public int length() {
    return length;
}

@Override
public String toString() {
    return new String(buffer, 0, length);
}

Common Follow-ups

Rope data structure for large text?

A rope is a balanced binary tree of strings. Each leaf holds a short string segment. Concatenation is O(1) — just create a new root with both trees as children. Insert/delete in the middle is O(log n) instead of O(n). Used in text editors (VS Code, Xi) for handling large files efficiently.

StringBuffer vs StringBuilder?

StringBuffer is synchronized (thread-safe) — every method acquires a lock. StringBuilder is not synchronized (faster). In single-threaded code (99% of cases), use StringBuilder. StringBuffer is a legacy class from Java 1.0; StringBuilder was added in Java 5 as the unsynchronized replacement.

Why is String immutable in Java?

Security: strings used in class loading, network connections, file paths can't be modified after creation. Thread safety: immutable objects are inherently thread-safe. Caching: hashCode can be cached (String pool). String pool: multiple references can safely share the same String object.

String intern pool?

JVM maintains a pool of unique strings. String.intern() returns the canonical reference. String literals are automatically interned. "hello" == "hello" is true (same pool reference). new String("hello") == "hello" is false (different objects). Saves memory when many identical strings exist.

Edge Cases & Gotchas

Loop concatenation trap — for(…) s += x compiles to creating a new StringBuilder per iteration in older Java. Even in modern Java, the JIT may not always optimize this. Always use explicit StringBuilder in loops.
Growth factor matters — 2× is standard, but 1.5× (like ArrayList) wastes less space at the cost of more resizes. Java's real StringBuilder uses oldCapacity * 2 + 2.
ensureCapacity max(2×, min) — The Math.max handles appending a string longer than the current capacity in one go. Without it, a single large append could exceed 2× and cause an out-of-bounds write.
