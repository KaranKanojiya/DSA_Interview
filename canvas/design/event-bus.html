Event Bus — Implement from Scratch

In-process event emitter with on(event, callback), off(event, callback), once(event, callback), and emit(event, data). Uses CopyOnWriteArrayList for thread-safe iteration during dispatch. Synchronous emission — callbacks run on the emitter's thread.

Core Idea

What is an Event Bus?

A publish-subscribe mechanism within a single process. Components register callbacks for named events (on). When an event is emitted, all registered callbacks are invoked synchronously with the provided data.

Decouples producers and consumers — the emitter doesn't know who's listening.

Key Operations

  • on(event, cb) — register a persistent listener
  • once(event, cb) — register a one-shot listener that auto-removes
  • off(event, cb) — unsubscribe a specific callback
  • emit(event, data) — fire event, invoke all listeners

Operations — Step by Step

on(event, cb)

  1. computeIfAbsent creates CopyOnWriteArrayList for new events
  2. Add callback to the listener list
  3. Callback persists until explicitly removed with off()

emit(event, data)

  1. Get listener list (or empty list via getOrDefault)
  2. Iterate and call cb.accept(data) for each
  3. Synchronous — runs on caller's thread
  4. CopyOnWriteArrayList allows safe concurrent modification
1

Fields — Listener Map

state

A HashMap of event names to CopyOnWriteArrayList of Consumer callbacks. CopyOnWrite allows safe iteration during emit while listeners may be added/removed.

private final Map<String, List<Consumer<Object>>> listeners = new HashMap<>();
2

on(event, callback) — Subscribe

register listener
public void on(String event, Consumer<Object> callback) {
    listeners
        .computeIfAbsent(event, k -> new CopyOnWriteArrayList<>())
        .add(callback);
}
3

off(event, callback) — Unsubscribe

remove listener
public void off(String event, Consumer<Object> callback) {
    List<Consumer<Object>> cbs = listeners.get(event);
    if (cbs != null) cbs.remove(callback);
}
4

once(event, callback) — One-Shot Listener

self-removing wrapper

Creates an anonymous Consumer wrapper that invokes the real callback, then removes itself via off(). The wrapper must reference this (itself) for removal.

public void once(String event, Consumer<Object> callback) {
    Consumer<Object> wrapper = new Consumer<>() {
        public void accept(Object data) {
            callback.accept(data);       // invoke real callback
            off(event, this);            // self-remove from listeners
        }
    };
    on(event, wrapper);                  // register wrapper as listener
}
5

emit(event, data) — Fire Event

dispatch
public void emit(String event, Object data) {
    for (Consumer<Object> cb : listeners.getOrDefault(event, List.of())) {
        cb.accept(data);                 // synchronous dispatch
    }
}

Common Follow-ups

Priority listeners?

Assign a priority to each listener. Store in a priority queue or sorted list per event. Higher-priority listeners fire first. Useful for middleware chains where order matters (e.g., authentication before authorization). Guava EventBus uses @Subscribe with no priority — all equal.

Wildcard events?

Support patterns like user:* that match user:login, user:logout, etc. On emit, check all registered patterns against the event name. Node.js EventEmitter2 supports this. Implementation: iterate all registered patterns, use glob or prefix matching. Adds overhead to emit but increases flexibility.

Error handling in callbacks?

If a callback throws, should emit continue to the next listener or abort? Options: (1) catch and log errors per callback, continue; (2) stop on first error; (3) collect all errors, throw aggregated exception after all callbacks run. Node.js EventEmitter has a special "error" event — unhandled error events crash the process.

Backpressure / async emit?

Current implementation is synchronous — slow listeners block the emitter. Solutions: (1) emit on a separate thread pool; (2) queue events and process asynchronously; (3) use reactive streams (Project Reactor, RxJava) for backpressure control. Trade-off: async emit loses ordering guarantees unless you use a single-threaded executor.

Guava EventBus vs custom?

Guava EventBus: annotation-based (@Subscribe), type-based dispatch (not string events), automatic method discovery, dead event handling. Limitations: no once(), no priority, synchronous only (AsyncEventBus for async). Your custom EventBus: string-based events, explicit registration, more flexible but less type-safe.

Edge Cases & Gotchas

ConcurrentModificationException — Without CopyOnWriteArrayList, removing a listener inside emit() (as once() does) would throw. CopyOnWriteArrayList creates a snapshot on mutation, so the iterating emit loop is unaffected.
Lambda identity for off() — off(event, cb) uses reference equality. If you register a lambda, you must keep a reference to remove it. Anonymous lambdas created inline can't be removed — use once() instead or store the reference.
Memory leaks — Listeners hold references to their enclosing objects. Forgetting to call off() prevents garbage collection. Use WeakReference wrappers or ensure cleanup in lifecycle methods (e.g., onDestroy()).
Thread safety of the map itself — listeners is a plain HashMap. If on() and emit() are called from different threads, the map itself needs synchronization (or use ConcurrentHashMap). CopyOnWriteArrayList only protects the individual lists.
