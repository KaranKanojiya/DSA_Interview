CompletableFuture — Implement from Scratch

A container for an async result that may not be available yet. complete(value) sets the result, notifies waiters, and runs chained callbacks. get() blocks until completed. thenApply(fn) chains transformations — runs immediately if already completed, else queues the callback for later.

Core Idea

What is a CompletableFuture?

A promise — a placeholder for a value that will be available later. A producer calls complete(value) when the result is ready. Consumers either block with get() or chain transformations with thenApply(fn).

Similar to JavaScript's Promise, Scala's Future, or Python's asyncio.Future.

Key Design Decisions

  • complete() — sets value, wakes blocked threads, runs all queued callbacks
  • get() — blocks via wait() until completed
  • thenApply(fn) — if done: run fn immediately; else: queue for later
  • completeExceptionally() — error path propagation

thenApply — Two Scenarios

Already completed

  1. Check completed == true
  2. Apply fn to result immediately
  3. next.complete(fn.apply(result))
  4. Return the already-completed next future

Not yet completed

  1. Check completed == false
  2. Add fn to the callbacks list
  3. When complete() is later called, it runs fn
  4. Return next future (will be completed later)
4

Operations — Step by Step

complete(value)

  1. Check not already completed (else throw)
  2. Set result = value, completed = true
  3. notifyAll() — wake all get() waiters
  4. Iterate callbacks: cb.apply(value)

get() — blocking

  1. while (!completed) wait()
  2. If error was set → throw the exception
  3. Return the result value
  4. Subsequent calls return immediately

Fields — State Container

generic

Stores the result (or error), completion flag, and a list of queued callbacks for thenApply chains.

public class MyCompletableFuture<T> {

    private T result;
    private Exception error;
    private boolean completed = false;
    private final List<Function<T, ?>> callbacks = new ArrayList<>();
}
2

complete(value) — Set Result & Notify

producer side
public synchronized void complete(T value) {
    if (completed) throw new IllegalStateException("Already completed");
    this.result = value;
    this.completed = true;
    notifyAll();                        // wake all get() waiters
    for (Function<T, ?> cb : callbacks) {
        cb.apply(value);                // run queued thenApply callbacks
    }
}
3

completeExceptionally(error)

error path
public synchronized void completeExceptionally(Exception error) {
    this.error = error;
    this.completed = true;
    notifyAll();
}
4

get() — Block Until Complete

consumer side
public synchronized T get() throws Exception {
    while (!completed) {
        wait();                         // release monitor, sleep
    }
    if (error != null) throw error;     // propagate exception
    return result;
}

thenApply(fn) — Chain Transformations

monadic compose

Returns a new future. If already completed, applies fn and completes the new future immediately. Otherwise, queues a callback that will complete the new future when this one completes.

@SuppressWarnings("unchecked")
public <U> MyCompletableFuture<U> thenApply(Function<T, U> fn) {
    MyCompletableFuture<U> next = new MyCompletableFuture<>();
    synchronized (this) {
        if (completed) {
            // Already done — apply immediately
            try { next.complete(fn.apply(result)); }
            catch (Exception e) { next.completeExceptionally(e); }
        } else {
            // Not done — queue callback for later
            callbacks.add(val -> {
                try { next.complete(fn.apply((T) val)); }
                catch (Exception e) { next.completeExceptionally(e); }
                return null;
            });
        }
    }
    return next;
}

Common Follow-ups

thenCompose (flatMap)?

thenApply transforms T → U. thenCompose transforms T → Future<U> and flattens — avoids Future<Future<U>>. Like flatMap in streams. Implementation: when the first future completes, call fn to get a new future, then chain the inner future's completion to the outer next future.

thenCombine (join 2 futures)?

Waits for two futures to complete, then combines their results with a BiFunction. Implementation: both futures register a callback. Each callback checks if the other is also complete. When both are done, apply the combine function and complete the result future. Use AtomicInteger to count completions.

exceptionally (error handler)?

Catches exceptions from upstream futures and provides a fallback value. Like .catch() in JavaScript Promises. Implementation: return a new future. If this future completes normally, pass through. If exceptionally, apply the error handler function and complete the next future with its return value.

allOf / anyOf?

allOf: returns a future that completes when ALL input futures complete. Use AtomicInteger countdown. anyOf: completes when the FIRST input future completes. Each input registers a callback that completes the result (subsequent calls are no-ops since complete() throws on double-complete). Race pattern.

CompletionStage interface?

Java's CompletionStage interface defines the full API: thenApply, thenCompose, thenCombine, thenAccept, thenRun, handle, exceptionally, whenComplete. CompletableFuture implements it. Each method has *Async variants that run on a thread pool (default: ForkJoinPool.commonPool).

Edge Cases & Gotchas

Double complete — Calling complete() twice must throw IllegalStateException. Without this check, the result could change after consumers have already read it. Java's CompletableFuture silently ignores the second call (returns false).
thenApply before vs after complete — The callback must work in both scenarios: (1) queued before completion → runs when complete() is called, (2) registered after completion → runs immediately. Both paths must be inside synchronized to avoid the race where complete() and thenApply() interleave.
Error propagation in chains — If fn.apply() throws in thenApply, the next future must be completed exceptionally (not silently swallowed). This ensures errors propagate through the chain, just like rejected Promises in JavaScript.
Callback runs on complete() thread — All callbacks run synchronously on whichever thread calls complete(). A slow callback delays subsequent callbacks and the complete() caller. Java's real CompletableFuture offers thenApplyAsync to run on a separate thread pool.
