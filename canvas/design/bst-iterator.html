BST Iterator — Implement from Scratch

Stack-based in-order traversal of a Binary Search Tree. pushAllLeft() queues the leftmost path; next() pops and processes the right subtree. Each node is pushed and popped exactly once across all calls, yielding O(1) amortized per operation. LeetCode #173.

Core Idea

What is a BST Iterator?

An iterator that yields BST elements in sorted (in-order) order — smallest to largest — without flattening the entire tree into a list upfront.

next() returns the next smallest, hasNext() checks if more exist.

Why stack-based?

  • O(h) space instead of O(n) for a full flatten
  • Stack simulates the call stack of recursive in-order traversal
  • Lazy evaluation — only processes nodes as needed
  • Interviewers want to see you avoid List<Integer> pre-sort

Key insight: The stack always holds the path from the root to the current "next smallest" node — only left edges. Each node is pushed once and popped once across all calls, so the total work is O(n) spread over n calls = O(1) amortized.

Operations — Step by Step

pushAllLeft(node)

  1. While node is not null:
  2. Push node onto stack
  3. Move to node.left

Queues the leftmost path — guarantees stack top is always the next smallest.

next()

  1. Pop top of stack → this is the next smallest
  2. If popped node has a right child → pushAllLeft(right)
  3. Return popped node's value

Processing the right subtree ensures in-order continues correctly.

3

pushAllLeft(node) — Queue Leftmost Path

helper

Pushes node and all its left children onto the stack. After this, the stack top is the smallest node in that subtree.

private void pushAllLeft(TreeNode node) {
    while (node != null) {
        stack.push(node);
        node = node.left;
    }
}
4

next() — O(1) Amortized

return next smallest
public int next() {
    if (!hasNext()) throw new NoSuchElementException("No more elements");

    // Pop the top — this is the next smallest
    TreeNode current = stack.pop();

    // If it has a right subtree, push all left children
    // This ensures the NEXT call returns the correct value
    if (current.right != null) {
        pushAllLeft(current.right);
    }

    return current.val;
}
5

hasNext() — O(1)

check remaining
public boolean hasNext() {
    return !stack.isEmpty();
}

Common Follow-ups

Flatten BST to sorted list?

Simply call next() in a loop and collect all values. Or do a full recursive in-order traversal. The iterator approach is lazy — better when you only need the first few elements.

Merge 2 BST iterators?

Create two BSTIterator instances. Merge like merging two sorted lists: compare peek() from each, advance the smaller. Total time O(n + m), space O(h1 + h2).

Implement peek()?

Just return stack.peek().val without popping. O(1) since the stack top is always the next smallest. Could also cache the next value in a field.

General tree iterator (not BST)?

For a generic tree, choose your traversal order (pre/in/post/level). Level-order uses a Queue instead of a Stack. For n-ary trees, push children in reverse order for pre-order. The pattern is the same: use an explicit data structure to simulate recursion.

Edge Cases & Gotchas

Right-skewed tree — If the BST is a straight right chain (degenerate), the constructor pushes only the root. Each next() call pushes one node. Stack never exceeds 1 element — space is O(1) in this case.
Left-skewed tree — Constructor pushes all n nodes. The first next() call is O(1), but the constructor itself is O(n). Stack size = O(n) = O(h) since h = n for a skewed tree.
Deque vs Stack — Java's Stack class is synchronized (legacy). Use ArrayDeque as a stack for better performance. Push/pop from the same end.
NoSuchElementException — Always check hasNext() before next(). Production iterators should throw a clear exception, not return a sentinel value.
