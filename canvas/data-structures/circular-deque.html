Circular Deque — Implement from Scratch

Fixed-size circular buffer backed by an array. front and rear pointers wrap around using modular arithmetic ((index ± 1 + capacity) % capacity). All operations O(1) time, O(capacity) space. No linked list overhead — cache-friendly and allocation-free after construction. LeetCode #641.

Core Idea

What is a Circular Deque?

A double-ended queue backed by a fixed-size array where the ends wrap around. When front decrements past index 0, it wraps to capacity - 1. When rear increments past the last index, it wraps to 0.

Insert and remove from both ends in O(1) — no shifting elements.

Why circular over linear?

  • Linear array wastes space — removed slots at the front can never be reclaimed
  • Circular buffer reuses freed slots by wrapping pointers
  • Cache-friendly: contiguous memory, no pointer chasing like linked list
  • Perfect for fixed-capacity scenarios (bounded queues, ring buffers)
2

Circular Array — Wrap-around Diagram

Modular arithmetic is the key trick. (index - 1 + capacity) % capacity handles backward wrap (e.g., 0→7), and (index + 1) % capacity handles forward wrap (e.g., 7→0).
Full vs Empty? Both have front == rear. Solutions: (1) track a size counter, (2) waste one slot — full when (rear + 1) % cap == front, or (3) use a boolean flag.

Operations — Step by Step

addFirst(val)

  1. Check if deque is full → return false
  2. front = (front - 1 + cap) % cap
  3. data[front] = val
  4. Increment size, return true

front wraps backward — think of it as growing "to the left"

addLast(val)

  1. Check if deque is full → return false
  2. data[rear] = val
  3. rear = (rear + 1) % cap
  4. Increment size, return true

rear wraps forward — grows "to the right"

removeFirst()

  1. Check if empty → return false
  2. front = (front + 1) % cap
  3. Decrement size, return true

Just advance the pointer — no need to clear the old slot

removeLast()

  1. Check if empty → return false
  2. rear = (rear - 1 + cap) % cap
  3. Decrement size, return true

Retreat the pointer — wraps backward just like addFirst

Fields & Constructor

setup
private int[] data;
private int front;     // index of the front element
private int rear;      // index of NEXT available slot at the back
private int size;
private final int capacity;

public CircularDeque(int k) {
    this.capacity = k;
    this.data = new int[k];
    this.front = 0;
    this.rear = 0;
    this.size = 0;
}

addFirst — Front Wraps Backward

O(1)
public boolean insertFront(int value) {
    if (size == capacity) return false;
    front = (front - 1 + capacity) % capacity;  // wrap backward
    data[front] = value;
    size++;
    return true;
}
Why + capacity? Java's % can return negative for negative operands. Adding capacity before the modulo guarantees a non-negative result: (0 - 1 + 8) % 8 = 7.
3

addLast — Rear Wraps Forward

O(1)
public boolean insertLast(int value) {
    if (size == capacity) return false;
    data[rear] = value;
    rear = (rear + 1) % capacity;  // wrap forward
    size++;
    return true;
}

removeFirst & removeLast

O(1)
public boolean deleteFront() {
    if (size == 0) return false;
    front = (front + 1) % capacity;
    size--;
    return true;
}
public boolean deleteLast() {
    if (size == 0) return false;
    rear = (rear - 1 + capacity) % capacity;
    size--;
    return true;
}
5

peekFirst & peekLast

O(1)
public int getFront() {
    if (size == 0) return -1;
    return data[front];
}
public int getRear() {
    if (size == 0) return -1;
    // rear points to NEXT slot, so actual last = rear - 1
    return data[(rear - 1 + capacity) % capacity];
}

isEmpty & isFull

helpers
public boolean isEmpty() { return size == 0; }
public boolean isFull()  { return size == capacity; }

Common Follow-ups

Sliding Window Maximum (LC #239)?

Use a monotonic deque — a deque that keeps elements in decreasing order. On each window slide: remove elements outside the window from the front, remove elements smaller than the new element from the back (they'll never be the max), then add the new element. The front of the deque is always the window max. O(n) total.

Circular Queue for OS scheduling?

Round-robin CPU scheduling uses a circular queue. Each process gets a time quantum. When its quantum expires, it's moved to the back of the queue. The circular buffer prevents memory waste from dequeued processes leaving "holes" at the front of a linear array.

Ring buffer for logging / network I/O?

Ring buffers are used in kernel networking (Linux io_uring), audio processing, and logging systems. The producer writes at rear, the consumer reads at front. When the buffer is full, the oldest entries are overwritten (lossy) or the producer blocks (lossless). Lock-free ring buffers use atomic CAS on the pointers.

Dynamic resizing?

To grow: allocate a new array of 2× size, copy elements starting from front in circular order to positions 0..size-1 in the new array, reset front=0 and rear=size. This is O(n) but amortized O(1) if you double each time (same as ArrayList).

Edge Cases & Gotchas

Full deque — Must check size == capacity before every insert. Forgetting this causes data corruption by overwriting existing elements.
Empty deque — getFront() and getRear() on an empty deque must return -1 (or throw). Don't access data[front] when size is 0.
Wrap-around boundary — The trickiest bug: getRear() must access data[(rear - 1 + capacity) % capacity], not data[rear]. The rear pointer points to the next available slot, not the last inserted element.
Negative modulo — In Java, (-1) % 8 == -1, not 7. Always add capacity before taking modulo when decrementing: (i - 1 + capacity) % capacity.
