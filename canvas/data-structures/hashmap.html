Core Idea

What is a HashMap?

A key-value store backed by an array of buckets. A hash function converts the key to an integer, and hash & (length-1) maps it to a bucket index. Collisions are handled by separate chaining — each bucket is a linked list of entries.

Average O(1) for get, put, remove. Worst case O(n) if all keys hash to the same bucket.

Why build from scratch?

  • Tests understanding of hashing, collision resolution, and resize/rehash
  • Explains why hashCode() and equals() contract matters
  • Foundation for ConcurrentHashMap, LinkedHashMap, LRU cache

How Hashing Works

Hash Function

Java's hashCode() returns a 32-bit int. But the bucket array is small (16 initially), so we need to compress it:

  1. h = key.hashCode()
  2. h = h ^ (h >>> 16) — spread higher bits into lower bits
  3. index = h & (length - 1) — fast modulo (power of 2)

Step 2 is critical: since & (length-1) only uses the lower bits, XORing with the upper 16 bits reduces collisions for keys that differ only in higher bits.

Load Factor & Resize

When size > capacity × 0.75, the array doubles and all entries are rehashed:

  • Load factor 0.75 — balance between space and time. Lower = fewer collisions but more memory.
  • Resize = 2× — keeps capacity as power of 2 (required for bitwise & trick)
  • Rehash — every entry gets a new index because length-1 changed
3

Bucket Array — Separate Chaining

Separate chaining: Each bucket holds a linked list. On collision, the new entry is inserted at the head of the chain — O(1) insertion. Walking the chain is O(k) where k is the chain length.

Entry — Key-Value Node

inner class

Each entry stores key, value, cached hash (avoid recomputing on resize), and a next pointer for chaining.

private static class Entry<K, V> {
    final K key;
    V value;
    final int hash;          // cached hash — avoid recomputing on resize
    Entry<K, V> next;      // next entry in the chain

    Entry(K key, V value, int hash, Entry<K, V> next) {
        this.key = key;
        this.value = value;
        this.hash = hash;
        this.next = next;
    }
}

Hash Function & Bucket Index

core hashing
// Why hash ^ (hash >>> 16)?
// Spreads higher bits into lower bits to reduce collisions
// when table size is power of 2 (& length-1 only uses lower bits)
private int hash(K key) {
    if (key == null) return 0;
    int h = key.hashCode();
    return h ^ (h >>> 16);
}

// & (length-1) instead of % length — faster, works because length is power of 2
private int bucketIndex(int hash) {
    return hash & (buckets.length - 1);
}

put(key, value) — O(1) avg

write path
public void put(K key, V value) {
    int hash = hash(key);
    int index = bucketIndex(hash);

    // Walk the chain — check if key already exists
    Entry<K, V> current = buckets[index];
    while (current != null) {
        if (current.hash == hash &&
            (current.key == key || (key != null && key.equals(current.key)))) {
            current.value = value;   // key found → update
            return;
        }
        current = current.next;
    }

    // Key not found → insert at HEAD of chain (O(1))
    buckets[index] = new Entry<>(key, value, hash, buckets[index]);
    size++;

    if (size > buckets.length * LOAD_FACTOR) {
        resize();
    }
}

remove(key) — O(1) avg

delete path
public V remove(K key) {
    int hash = hash(key);
    int index = bucketIndex(hash);

    Entry<K, V> current = buckets[index];
    Entry<K, V> prev = null;

    while (current != null) {
        if (current.hash == hash &&
            (current.key == key || (key != null && key.equals(current.key)))) {
            if (prev == null) {
                buckets[index] = current.next;  // head of chain
            } else {
                prev.next = current.next;        // middle/end
            }
            size--;
            return current.value;
        }
        prev = current;
        current = current.next;
    }
    return null;
}

resize() — Double & Rehash

O(n)
@SuppressWarnings("unchecked")
private void resize() {
    Entry<K, V>[] oldBuckets = buckets;
    buckets = new Entry[oldBuckets.length * 2];

    // Rehash every entry — index changes because length changed
    for (Entry<K, V> head : oldBuckets) {
        Entry<K, V> current = head;
        while (current != null) {
            Entry<K, V> next = current.next;
            int newIndex = bucketIndex(current.hash);
            current.next = buckets[newIndex];  // insert at head of new chain
            buckets[newIndex] = current;
            current = next;
        }
    }
}

Common Follow-ups

Thread-safe HashMap? (ConcurrentHashMap)

Java's ConcurrentHashMap uses segment locking (Java 7) or CAS + synchronized per-bucket (Java 8+). Multiple threads can read/write different buckets concurrently. Collections.synchronizedMap() wraps with a global lock — much worse throughput.

Null keys?

Java's HashMap supports one null key — stored at bucket index 0 (hash of null = 0). ConcurrentHashMap does not allow null keys or values. Our implementation handles null via the if (key == null) return 0 check in the hash function.

Java 8 Treeification

When a bucket chain exceeds 8 entries, Java converts it to a Red-Black Tree — O(log n) lookup instead of O(n). When it drops below 6, it converts back to a linked list. This protects against hash-flooding DoS attacks.

Custom hash function requirements?

The hashCode() / equals() contract: if a.equals(b), then a.hashCode() == b.hashCode(). The reverse is not required (collisions are fine). A good hash function distributes keys uniformly across buckets. Override both or neither.

Edge Cases & Gotchas

Hash collision ≠ same key — Always compare with equals() after hash match. Using == instead of equals() is the #1 bug — works for Integer cache (-128 to 127) but fails for larger values or Strings.
Resize triggers — Resize happens when size > capacity × loadFactor, not when a single bucket overflows. It's a global threshold, not per-bucket.
Insert at head of chain — New entries go at the head of the linked list (O(1) insertion). Walking to the tail would be O(k) for no benefit.
equals() vs == — Check hash first (fast integer compare), then == (same reference), then equals() (value equality). This three-step check is exactly what Java's HashMap does.
