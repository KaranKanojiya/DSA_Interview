Graph — BFS & DFS from Scratch

Adjacency list representation using Map<vertex, List<neighbors>>. BFS with a Queue explores level by level — finds shortest path in unweighted graphs. DFS with recursion explores as deep as possible before backtracking. The backbone of social networks, routing, dependency resolution, and hundreds of LeetCode problems.

Most real-world graphs are sparse → adjacency list is the default choice.

When BFS vs DFS?

  • BFS: shortest path (unweighted), level-order, closest nodes, minimum moves
  • DFS: cycle detection, topological sort, connected components, pathfinding in mazes, backtracking
  • Both work: reachability, counting components, graph traversal

BFS uses a Queue (FIFO). DFS uses a Stack or recursion (LIFO).

Graph with BFS & DFS Traversal

BFS visits level by level — all nodes at distance 1 before distance 2. This is why BFS finds shortest paths in unweighted graphs. DFS dives deep along one path before exploring alternatives.

→ [1, 2]

Vertex 3

Each vertex maps to a list of its neighbors. For undirected graphs, each edge appears in both lists. Total storage: O(V + 2E) = O(V + E).

BFS — Queue-Based (Level-Order)

O(V+E)
public List<Integer> bfs(int start) {
    List<Integer> result = new ArrayList<>();
    Set<Integer> visited = new HashSet<>();
    Queue<Integer> queue = new LinkedList<>();

    visited.add(start);
    queue.offer(start);

    while (!queue.isEmpty()) {
        int curr = queue.poll();      // dequeue front
        result.add(curr);

        for (int neighbor : adjList.getOrDefault(curr, Collections.emptyList())) {
            if (!visited.contains(neighbor)) {
                visited.add(neighbor);   // mark BEFORE enqueue to avoid duplicates
                queue.offer(neighbor);
            }
        }
    }
    return result;
}
Mark visited when enqueuing, not when dequeuing. If you mark when dequeuing, the same node can be enqueued multiple times by different neighbors, wasting time and space. This is the #1 BFS bug.

DFS — Recursive

O(V+E)
public List<Integer> dfs(int start) {
    List<Integer> result = new ArrayList<>();
    Set<Integer> visited = new HashSet<>();
    dfsHelper(start, visited, result);
    return result;
}

private void dfsHelper(int node, Set<Integer> visited, List<Integer> result) {
    visited.add(node);
    result.add(node);

    for (int neighbor : adjList.getOrDefault(node, Collections.emptyList())) {
        if (!visited.contains(neighbor)) {
            dfsHelper(neighbor, visited, result);  // recurse deeper
        }
    }
}

hasPath — Reachability Check

BFS/DFS
public boolean hasPath(int src, int dest) {
    if (src == dest) return true;
    Set<Integer> visited = new HashSet<>();
    Queue<Integer> queue = new LinkedList<>();
    visited.add(src);
    queue.offer(src);

    while (!queue.isEmpty()) {
        int curr = queue.poll();
        for (int neighbor : adjList.getOrDefault(curr, Collections.emptyList())) {
            if (neighbor == dest) return true;
            if (!visited.contains(neighbor)) {
                visited.add(neighbor);
                queue.offer(neighbor);
            }
        }
    }
    return false;
}

Common Follow-ups

Topological Sort (LC #207, #210)?

Kahn's BFS: compute in-degrees. Enqueue all nodes with in-degree 0. Process: decrement neighbors' in-degrees, enqueue when they hit 0. If result size < V, there's a cycle. O(V+E).

DFS: Run DFS, add node to result after all descendants are processed (post-order). Reverse the result. Cycle = back edge detected (node in current recursion stack).

Cycle Detection?

Undirected: BFS/DFS — if you visit a neighbor that's already visited and it's not the parent, there's a cycle. Or use Union-Find: if two endpoints of an edge are in the same set, cycle found.

Directed: DFS with 3 colors (white/gray/black). Gray → gray edge = back edge = cycle. Or use Kahn's: if topo sort doesn't include all nodes, there's a cycle.

Shortest Path: Dijkstra / Bellman-Ford?

Dijkstra: Greedy BFS with a min-heap (priority queue). Always process the closest unvisited node. O((V+E) log V) with a binary heap. Doesn't work with negative edges.

Bellman-Ford: Relax all edges V-1 times. O(V × E). Handles negative edges. One more pass detects negative cycles. Slower but more general.

Unweighted shortest path = plain BFS. Weighted = Dijkstra (no negative) or Bellman-Ford.

Connected Components / Bipartite?

Connected components: Run BFS/DFS from each unvisited node. Each run discovers one component. Count the number of runs = number of components.

Bipartite check: BFS with 2-coloring. Assign colors alternating by level. If a neighbor has the same color as the current node, the graph is NOT bipartite. O(V+E).

Edge Cases & Gotchas

Disconnected graph — BFS/DFS from one node won't visit all vertices. To traverse the entire graph, loop over all vertices and run BFS/DFS from each unvisited one. This is essential for counting connected components.
Self-loops — An edge from a node to itself. Your visited set prevents infinite loops, but be aware when checking for cycles — a self-loop is a cycle of length 1.
Directed vs Undirected — For undirected, addEdge adds to both adjacency lists. For directed, only add to the source's list. The distinction matters for cycle detection, topological sort, and strongly connected components.
DFS stack overflow — For very deep graphs (e.g., a 10^6 node chain), recursive DFS can overflow the call stack. Use iterative DFS with an explicit stack: Stack<Integer> stack = new Stack<>(), same logic but loop instead of recurse.
