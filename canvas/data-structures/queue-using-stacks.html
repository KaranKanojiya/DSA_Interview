Queue Using Two Stacks — Implement from Scratch

Two stacks: pushStack (enqueue) + popStack (dequeue). Transfer on empty popStack reverses order for FIFO. Each element is pushed and popped at most twice → amortized O(1). A classic interview question testing stack ↔ queue duality. LeetCode #232.

Core Idea

The Two-Stack Trick

A stack is LIFO, a queue is FIFO. Reversing the order of a stack gives FIFO. Use two stacks:

  • pushStack — all enqueue operations go here
  • popStack — all dequeue/peek operations come from here
  • When popStack is empty, transfer all elements from pushStack → popStack (reverses order)

The transfer makes the oldest element (first enqueued) land on top of popStack — FIFO order restored.

Why Amortized O(1)?

Each element goes through exactly 4 operations in its lifetime:

  1. Push onto pushStack — O(1)
  2. Pop from pushStack (during transfer) — O(1)
  3. Push onto popStack (during transfer) — O(1)
  4. Pop from popStack (dequeue) — O(1)

Total: 4 operations per element, all O(1). Even though a single transfer is O(k), each element is only transferred once → amortized O(1) per dequeue.

Operations — Step by Step

enqueue(value)

  1. Push value onto pushStack
  2. Done — always O(1)

dequeue()

  1. If popStack is empty → transfer()
  2. If still empty → throw (queue is empty)
  3. Pop from popStack and return

peek()

  1. Same as dequeue but use peek() on popStack
  2. Element stays on the stack

transfer()

  1. While pushStack not empty:
  2.   Pop from pushStack
  3.   Push onto popStack
  4. Reverses order — O(k) for k elements
Transfer only when popStack is empty. This is the key optimization. Don't transfer on every dequeue — only when needed. This ensures each element is transferred at most once.

dequeue() — O(1) amortized

FIFO
public E dequeue() {
    if (popStack.isEmpty()) transfer();
    if (popStack.isEmpty())
        throw new IllegalStateException("Queue is empty");
    return popStack.pop();
}

peek() — O(1) amortized

front element
public E peek() {
    if (popStack.isEmpty()) transfer();
    if (popStack.isEmpty())
        throw new IllegalStateException("Queue is empty");
    return popStack.peek();
}

transfer() — The Reversal Engine

O(k) batch
// Move all from pushStack → popStack
// Reverses order: LIFO → FIFO
private void transfer() {
    while (!pushStack.isEmpty()) {
        popStack.push(pushStack.pop());
    }
}

Common Follow-ups

Stack using two Queues?

The reverse problem (LeetCode #225). Approach 1: Make push O(n) — on push, enqueue to q2, then move all from q1 to q2, swap q1/q2. Approach 2: Make pop O(n) — on pop, move n-1 elements to q2, dequeue last one, swap. Both work, but less elegant than queue-from-stacks.

Circular Queue (bounded)

Fixed-size array with head and tail indices that wrap around using % capacity. All operations O(1) worst case. LeetCode #622. Useful for BFS, producer-consumer buffers, and ring buffers in networking.

Priority Queue?

Not FIFO — elements are dequeued by priority (min or max). Backed by a binary heap. Insert O(log n), extract-min O(log n). Used in Dijkstra's, Huffman coding, task scheduling. Java's PriorityQueue uses a min-heap.

Can you make both operations O(1) worst case?

Not with stacks alone — you need a true queue (linked list or circular array) for O(1) worst case on both enqueue and dequeue. The two-stack approach inherently has worst-case O(n) dequeue (during transfer), but amortized O(1) is achievable.

Edge Cases & Gotchas

Empty dequeue — Must check BOTH stacks are empty before throwing. If only pushStack is checked, you'll miss elements sitting in popStack. The two-check pattern (if empty → transfer, if still empty → throw) handles this correctly.
Interleaved operations — Enqueue 3 items, dequeue 1, enqueue 2 more, dequeue 3. The implementation handles this correctly because transfer only happens when popStack is empty — remaining elements in popStack are already in correct FIFO order.
Don't transfer eagerly — A common mistake is transferring on every dequeue/peek. This makes dequeue O(n) every time instead of amortized O(1). Only transfer when popStack is empty.
