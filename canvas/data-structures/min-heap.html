Min-Heap / Priority Queue — Implement from Scratch

A complete binary tree stored as an array where every parent ≤ its children. siftUp after insert restores the heap property upward; siftDown after extractMin restores it downward. The foundation of priority queues, top-K problems, and graph algorithms (Dijkstra, Prim).

Core Idea

What is a Min-Heap?

A complete binary tree where every node's value is ≤ its children's values. The root is always the minimum. Stored compactly in an array — no pointers needed.

Max-Heap is the same but every parent ≥ children. Just flip the comparison.

Array Representation

RelationshipFormula
Parent of i(i - 1) / 2
Left child of i2 * i + 1
Right child of i2 * i + 2

No wasted space — complete tree fills the array left to right, level by level.

siftUp & siftDown

siftUp (after insert)

  1. New element added at end of array (bottom-right of tree)
  2. Compare with parent: arr[(i-1)/2]
  3. If child < parent → swap
  4. Repeat until parent ≤ child or we reach root

Bubbles up at most log n levels (height of tree)

siftDown (after extractMin)

  1. Root removed, last element moved to root
  2. Compare with smaller child
  3. If parent > smaller child → swap
  4. Repeat until heap property restored or leaf reached

Bubbles down at most log n levels

Why swap with the smaller child? If you swap with the larger child, that larger value becomes the parent of the smaller child — violating the min-heap property. Always pick the smaller child to maintain the invariant.

Fields & Constructor

setup
private int[] heap;
private int size;

public MinHeap(int capacity) {
    this.heap = new int[capacity];
    this.size = 0;
}

private int parent(int i)  { return (i - 1) / 2; }
private int left(int i)    { return 2 * i + 1; }
private int right(int i)   { return 2 * i + 2; }

insert + siftUp

O(log n)
public void insert(int val) {
    if (size == heap.length) {
        heap = Arrays.copyOf(heap, heap.length * 2);  // grow if needed
    }
    heap[size] = val;    // place at the end
    siftUp(size);        // bubble up to correct position
    size++;
}

private void siftUp(int i) {
    while (i > 0 && heap[i] < heap[parent(i)]) {
        swap(i, parent(i));   // child smaller than parent → swap
        i = parent(i);        // move up
    }
}
3

extractMin + siftDown

O(log n)
public int extractMin() {
    if (size == 0) throw new NoSuchElementException("Heap empty");
    int min = heap[0];       // root is always the min
    heap[0] = heap[--size];  // move last element to root
    siftDown(0);             // push it down to correct position
    return min;
}

private void siftDown(int i) {
    while (left(i) < size) {
        int smallest = left(i);

        // pick the smaller child
        if (right(i) < size && heap[right(i)] < heap[smallest]) {
            smallest = right(i);
        }

        if (heap[i] <= heap[smallest]) break;  // heap property satisfied

        swap(i, smallest);
        i = smallest;  // move down
    }
}

peek & swap

helpers
public int peek() {
    if (size == 0)
        throw new NoSuchElementException();
    return heap[0];  // O(1) — root is min
}
private void swap(int i, int j) {
    int tmp = heap[i];
    heap[i] = heap[j];
    heap[j] = tmp;
}

Common Follow-ups

Top-K elements (LC #215)?

Use a min-heap of size K. For each element: if heap size < K, insert. If element > heap.peek(), extractMin and insert. At the end, the heap contains the K largest elements. Root = Kth largest. Time: O(n log K).

Merge K sorted lists (LC #23)?

Insert the head of each list into a min-heap. Extract the minimum, add it to the result, and insert that node's next into the heap. Repeat until the heap is empty. Time: O(N log K) where N = total elements, K = number of lists.

Median finder with 2 heaps (LC #295)?

Use a max-heap (lower half) and a min-heap (upper half). Balance so that max-heap size ≥ min-heap size and the difference is at most 1. Median = max-heap root (odd count) or average of both roots (even count). Insert/balance: O(log n).

Why is heapify O(n), not O(n log n)?

Bottom-up heapify calls siftDown starting from the last internal node up to the root. Nodes near the bottom (which are the majority) sift down very few levels. The sum of work across all nodes forms a geometric series that converges to O(n). This is different from inserting n elements one by one (which would be O(n log n)).

Edge Cases & Gotchas

Empty heap — extractMin() and peek() on an empty heap must throw or return a sentinel. Always check size == 0 first.
Single element — After extracting from a 1-element heap, siftDown should be a no-op since left(0) = 1 >= size. Make sure your loop condition handles this.
siftDown: check right child exists — Left child existing doesn't guarantee right child exists. Always check right(i) < size before comparing heap[right(i)], otherwise you'll get an ArrayIndexOutOfBoundsException.
Min-Heap vs Max-Heap — The only difference is the comparison direction. For max-heap, flip < to > in siftUp and siftDown. Java's PriorityQueue is a min-heap by default; pass Collections.reverseOrder() for max-heap.
