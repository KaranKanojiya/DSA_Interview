Core Idea

What is a Thread Pool?

A fixed set of worker threads that continuously pull tasks from a shared queue. Instead of creating a new thread per task (expensive OS operation), you reuse a pre-created set of threads.

submit(task) → task enters queue → idle worker picks it up → executes → loops back for next task.

Why Thread Pools?

  • Thread creation is expensive — OS allocates stack memory (~512KB–1MB), kernel scheduling overhead
  • Unbounded threads → OOM, context-switch thrashing
  • Pool amortizes cost — threads created once, reused thousands of times
  • Controls concurrency level — prevents resource exhaustion

Shutdown Semantics

shutdown()

  • Sets isShutdown flag via AtomicBoolean
  • No new tasks accepted — submit() throws IllegalStateException
  • Existing tasks in queue still execute

awaitTermination()

  • Calls worker.join(5000) on each worker
  • Blocks caller until all workers finish (or timeout)
  • Workers exit when: isShutdown && queue.isEmpty()

Worker Inner Class

extends Thread

Each Worker is a Thread that loops: poll task from queue → execute → repeat. Daemon threads don't prevent JVM shutdown.

private static class Worker extends Thread {
    private final BlockingQueue<Runnable> queue;
    private final AtomicBoolean isShutdown;

    Worker(int id, BlockingQueue<Runnable> queue, AtomicBoolean isShutdown) {
        super("Worker-" + id);
        this.queue = queue;
        this.isShutdown = isShutdown;
        this.setDaemon(true);
    }

    @Override
    public void run() {
        // Worker loop: keep running until shutdown AND queue empty
        while (!isShutdown.get() || !queue.isEmpty()) {
            try {
                // poll(100ms) — allows periodic shutdown check
                Runnable task = queue.poll(100, TimeUnit.MILLISECONDS);
                if (task != null) {
                    task.run();  // execute on THIS worker thread
                }
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
                break;
            } catch (Exception e) {
                // Worker survives task failure — keeps processing
            }
        }
    }
}

Fields & Constructor

pool setup
private final Worker[] workers;
private final BlockingQueue<Runnable> taskQueue;
private final AtomicBoolean isShutdown;

public MyThreadPool(int poolSize) {
    this.taskQueue = new LinkedBlockingQueue<>();   // unbounded task queue
    this.isShutdown = new AtomicBoolean(false);
    this.workers = new Worker[poolSize];

    // Create and start all worker threads eagerly
    for (int i = 0; i < poolSize; i++) {
        workers[i] = new Worker(i, taskQueue, isShutdown);
        workers[i].start();
    }
}

submit(task)

O(1)
public void submit(Runnable task) {
    if (isShutdown.get()) {
        throw new IllegalStateException("ThreadPool is shutdown");
    }
    taskQueue.offer(task);  // O(1) add to queue — worker will pick it up
}

shutdown() & awaitTermination()

graceful stop
public void shutdown() {
    isShutdown.set(true);  // AtomicBoolean — visible to all workers
    // Workers finish current tasks + drain queue, then exit
}

public void awaitTermination() throws InterruptedException {
    for (Worker worker : workers) {
        worker.join(5000);  // wait up to 5 seconds per worker
    }
}

Common Follow-ups

Dynamic sizing (cached pool)?

Create threads on demand up to a max, idle threads die after timeout. Java's Executors.newCachedThreadPool() uses a SynchronousQueue — each submit blocks until a worker picks it up or a new thread is created. Track idle time per worker and terminate if exceeds keep-alive.

Rejection policy?

When both pool and queue are full: AbortPolicy (throw exception), CallerRunsPolicy (caller thread executes task — provides backpressure), DiscardPolicy (silently drop), DiscardOldestPolicy (drop oldest queued task). Java's ThreadPoolExecutor supports all four via RejectedExecutionHandler.

Scheduled thread pool?

Use a DelayQueue (priority queue ordered by execution time). Each task wraps a delay. Workers call delayQueue.take() which blocks until the earliest task is due. Supports schedule(task, delay) and scheduleAtFixedRate().

ForkJoinPool work-stealing?

Each worker has its own deque. Workers steal from other workers' deques when their own is empty. Optimized for recursive divide-and-conquer tasks. Used by Java's parallel streams. Steals from the tail (LIFO locally, FIFO stealing) to maximize cache locality.

Edge Cases & Gotchas

Task throws exception — Worker catches Exception in the run loop and continues. Without this, a single bad task would kill the worker thread, reducing pool capacity permanently.
Shutdown during execution — shutdown() only sets a flag. Workers finish their current task AND drain remaining queued tasks before exiting. This is "graceful" shutdown.
Submit after shutdown — Must throw IllegalStateException. Check isShutdown flag in submit(). Using AtomicBoolean ensures visibility across threads without explicit synchronization.
Daemon threads — Workers are set as daemon so they don't prevent JVM exit. Without this, if you forget to call shutdown(), the program hangs forever because non-daemon threads keep the JVM alive.
poll() vs take() — take() blocks indefinitely. poll(timeout) returns null after timeout, letting the worker check the shutdown flag. This is why the loop condition works: !isShutdown || !queue.isEmpty().
